Admission reads GPU KV cache capacity N from this server startup's log segment
and reserves at most floor(0.9 * N) tokens across in-flight requests. Each
request reserves its frozen prompt_tokens + 8192 output tokens + 4096 overhead
tokens. Both this total token budget and the current profile's sequence limit
must fit; 64 is a ceiling, not a guaranteed simultaneous request count. The
queue remains FIFO and does not skip a blocked head request. If this startup
does not report KV capacity, admission uses an explicit fallback of at most
32 in-flight requests; it does not reuse an older startup's capacity report.

The downloader uses direct hf-mirror.com requests with trust_env=False;
it supports Range resume, retries, and a 2 GiB source-disk free-space floor.
Completed downloads do not require the laptop or its port-10820 SSH proxy.

Only selected images are packed on the persistent disk; no image-file expansion.
Preparation checks a 15 GiB persistent-disk reserve before each shard, every
100 source rows, before inserting a new image BLOB, and before final export.
An interrupted/failed shard rolls back; completed shard transactions remain
resumable. Source counts and selected counts are both checked before freezing.
Selection or source-manifest changes are rejected rather than mixed into a DB.
Parquet footer estimates put all-source decoded image payloads at ~31.25 GiB
before subset filtering and global SHA deduplication; the final DB is measured
in dataset_manifest.json. The original cancelled packed DB is not reused.
