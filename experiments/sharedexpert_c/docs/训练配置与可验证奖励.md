这是固定子集实验，不能表述成完整使用上述大型数据集的全部训练分布。`hf-mirror.com` 只承担固定上游版本的字节传输；来源身份仍是表中的原始仓库。没有执行任意数据集加载脚本。31 个 LFS 原始载荷已逐个重新计算 SHA256 并与上游匹配，记录在 [source_validation.json](../data_pipeline/prepared/source_validation.json)。官方 TallyQA/CLEVR 的两个非 LFS 注释压缩包保存了本地复现哈希，不声称拥有上游未提供的校验和。

ViRL 图像包的上游 SHA256 为 `49e6485a02815430fe4a468a25c03c3514adf8c2b68135068fc36c7656d8ad27`；所需 9,960 张归档图像均经 CRC 校验。数据整理按单来源顺序进行，图像恢复使用 4 个有界 IO worker，避免并行读取多个大池造成容器内存溢出。

### 2.3 采样顺序与复用规则

每个教师先用 `seed = 20261019 + sum(ord(c) for c in teacher)` 创建独立随机数生成器，再对每个来源池的记录牌组打乱。来源记录全部用过一次后才重新洗牌并重复使用。因此，Geometry3K 的重复是受审计的固定预算复用，而非动态补采直到答对。

| 教师 | 数据顺序 seed |
|---|---:|
| `perception` | 20262100 |
| `reasoning` | 20261985 |
| `generalist` | 20262089 |

每 200 行先按上表生成精确数量的来源标签，再打乱这些标签，依次从对应牌组取题。每个 prepared 文件仍有 60 个周期；当前训练只消费前 15 个周期，即 3,000 行。训练端 **`data.shuffle=False`**，不再次破坏此顺序。batch 30 不整除 200，因此训练边界上每 **600 行 / 20 step** 覆盖三个完整周期，来源配比精确成立；全程也精确成立，单个 30 行 batch 不强制逐来源比例一致。

通用教师与 specialist 有意复用相同合格训练池，采用各自固定顺序抽样，并未要求三位教师之间题目完全互斥。这落实了用户的专家数据复用要求；当前可比性来自每教师 3,000 次暴露与一致训练超参数。IF 的隔离要求具体作用于**通用教师内部**：`int(pixel_sha256[:8],16) % 5 == 0` 的 VQAv2 图像属于 IF，其余属于普通 VQA；其他通用来源中落入 IF 图像集合的记录也排除，其中 TallyQA 33 条、RefCOCO 51 条，因此通用教师这两个池略小。COCO 原始图像 ID 也用于抵抗编码变化造成的隔离失效。

### 2.4 去污染与审计边界

1. 训练前冻结 [统一评测清单](../evaluation/suite.jsonl)，共 3,423 行，其中含 RefCOCO 原始 UNC val 的 500 条表达、439 张图像。评测答案不用于 RL 标签、训练采样偏好或路由训练。
2. 图像身份定义为 `SHA256(struct.pack('>II', width, height) + RGB像素字节)`，与评测实现一致；训练源移除任何匹配的评测图像。VQAv2 和 TallyQA 另按原始 RefCOCO val 的 COCO 图像 ID 排除，即使图像编码不同也保留这一检查。
3. 来源内部对相同图像/规范化问题去重。不同图像上的常见问题模板保留并记录，因为仅同一句问题并不代表同一道视觉题。RefCOCO 同图同问题却指向不同框的 7 个冲突对整体排除。
4. 对长数学问题做 NFKC、大小写和空白规范化后检查与评测的精确问题匹配；阈值为 40 字符。ViRL 与 Geometry3K/MMK12 进一步按图像、至少 80 字符且含数字的问题、以及原始 MMK12 UUID 去重。
5. ViRL release 的“train”名称不足以证明来源均为训练集。全 release 已识别 **2,052 条原始 MMK12 test 派生记录**，其中 `MMK12` 1,843 条、`MMK12Converted` 209 条，全部列入禁止集；本轮 10,000 条 reservoir 中命中 520 条并移除。详见 [原始 split 审计](../data_pipeline/raw/virl39k_original_split_audit.json)。
6. 最终独立审计重新计算全部 **24,949 个不同训练图像路径**的 RGB 哈希，确认文件均存在、评测图像重叠为 0、已知 ViRL 原始 test 派生记录为 0、IF 与通用教师其他来源图像重叠为 0。

这些检查覆盖已知原始 split、精确图像/文本与来源身份；它们不能证明所有裁剪、近似图像、改写问题或其他未识别派生数据都不存在。该边界应在论文数据说明中保留。

## 4. 实际 GRPO 目标

对于一个 prompt 的八个响应，规则奖励为 \(r_i\in[0,1]\)。奖励只写入响应最后一个有效 token，其余 token 的原始奖励为 0。GRPO 按完整响应的总奖励形成组内 advantage：

\[
\bar r=\frac{1}{8}\sum_{i=1}^{8}r_i,\qquad
s=\sqrt{\frac{1}{7}\sum_{i=1}^{8}(r_i-\bar r)^2},\qquad
A_i=\frac{r_i-\bar r}{s+10^{-6}}.
\]

这里使用 `torch.std` 的样本标准差，分母是 7。\(A_i\) 广播到响应的所有有效 token；prompt 与 padding 不进入该响应损失。八个奖励相同的组满足 \(A_i=0\)，继续计入采样预算，没有额外丢弃、补采或更换问题。

令 \(\ell_{\theta,it}\)、\(\ell_{\mathrm{old},it}\) 分别为更新中的 actor 与更新前 actor 对已采样 token 的 log probability，\(\ell_{v,it}\) 为 vLLM rollout 的 raw log probability。实现采用：

\[
\rho_{it}=\exp\!\left(\operatorname{clip}(\ell_{\theta,it}-\ell_{\mathrm{old},it},-20,20)\right),
\]

\[
U_{it}=\min\bigl(\rho_{it}A_i,\ \operatorname{clip}(\rho_{it},0.8,1.2)A_i\bigr),\qquad
\widetilde U_{it}=
\begin{cases}
\max(U_{it},3A_i),& A_i<0,\\
U_{it},& A_i\ge0.
\end{cases}
\]

rollout 数值修正的 token 权重为 \(c_{it}=\min(\exp(\ell_{\mathrm{old},it}-\ell_{v,it}),2)\)，计算时附加数值稳定的 log-ratio 裁剪，并视为不求导的权重。最终损失为：

\[
\mathcal L(\theta)=-\frac{1}{N}\sum_{i=1}^{N}\frac{1}{T_i}
\sum_{t=1}^{T_i}c_{it}\widetilde U_{it},\qquad N=30\times8=240.
\]

其中 \(T_i\) 为响应有效 token 数。没有 KL 项、熵项、额外监督蒸馏项或长度奖励。importance weight 针对 vLLM 与训练前向的数值差异，不是 reference-policy KL 正则。日志中的 `actor/ppo_kl` 是 PPO ratio 的诊断量，即使非零也不代表开启了 KL 惩罚；部分 importance-weight 最大值统计在 cap 前计算，日志值超过 2 不等于实际 loss 权重没有 cap。

## 5. 可验证奖励与输出门控

奖励由 [rewards.py](../rewards.py) 和 [reward_manager.py](../training/reward_manager.py) 本地计算，不调用 LLM judge，也不训练奖励模型。所有任务共享外层规则：

\[
r=G_{\mathrm{end}}\,G_{\mathrm{final}}\,r_{\mathrm{content}},\qquad r\in[0,1].
\]

\(G_{\mathrm{end}}\) 检查响应正常结束；\(G_{\mathrm{final}}\) 检查可提取的最终答案格式。格式正确本身没有正奖励，内容错误仍为 0。任务之间没有另外乘以不同 reward scale；来源权重只控制数据采样数量。

### 5.1 结束、thinking 与格式

| 条件 | 处理 |
|---|---|
| 响应最后一个有效 token | 必须是 Qwen 的 `<\|im_end\|>` 或 `<\|endoftext\|>`；两种合法 EOS 均识别 |
| 达到长度上限但未正常 EOS | 记 `truncated=1`，整条奖励 0，即使此前出现正确 boxed 答案 |
| thinking 区域 | 保留原始标记用于核验；有 `</think>` 时只读取最后一个 `</think>` 之后的 final |
| 未闭合 thinking | 响应自身含 `<think>`，或 prompt 最后 64 token 显示已开启且未关闭 thinking，而响应未给出 `</think>`，则无有效 final，奖励 0 |
| 非 JSON 任务 | final 中最后一个完整、非空的 `\boxed{...}` 为答案；支持嵌套花括号，转义字面花括号不改变层级 |
| 多个 boxed | 只使用最后一个；若后来出现未闭合的 boxed，不能回退采信更早的答案 |
| IF JSON 任务 | 整个 final 必须是合法 JSON 对象，且恰好一个 `answer` 键、字符串值；拒绝重复键、额外键、NaN/Infinity、代码围栏及对象外说明文字 |

EOS 门控基于有效长度和最终 token，而非仅靠字符串中是否出现答案。IF 检查作用于 thinking 结束后的 final；原始思考过程可保留。非 JSON final 允许解释文字，但计分内容仅是最后完整 boxed 内的答案。

每条响应记录 `score`、`accuracy`、`format_valid`、`truncated`、来源 `audit_source`、`group_uid`、prompt/response token 数与 prompt 截断情况。`format_valid=1` 只表示最终答案抽取结构通过；例如 boxed 中装入不合法 bbox 时内容分仍为 0，不能把该字段当作任务答案合法或正确的证明。

### 5.2 TallyQA / CLEVR：精确答案

任务为 `exact`，内容奖励：

\[
r_{\mathrm{exact}}=\max_{a\in\mathcal A}\mathbf 1[\operatorname{Equal}_{\mathrm{exact}}(p,a)].
\]

答案先 NFKC 规范化、casefold、去首尾并合并空白；完整包裹的 `\text{...}` / `\mathrm{...}` 可解开；英文 none/zero 至 ten 映射为数字。两边均为有限数值时允许分数和百分数表示，以 `rel_tol=1e-9, abs_tol=1e-9` 比较；其他情况要求规范化后字符串相等。这里不用 VQA 的强标点清洗，以免负号或符号信息被误删。

输出例子：`\boxed{3}`、`\boxed{red}`。对象数答错、颜色答错或只满足 boxed 格式均为 0。

### 5.3 Geometry3K / MMK12 / ViRL39K：数学等价

任务为 `math`，\(r_{\mathrm{math}}=\max_{a\in\mathcal A}\mathbf1[\operatorname{MathEqual}(p,a)]\)。判定按下面的有限规则执行，**不是通用数学正确性 oracle**。

1. 可信 gold 若自身包裹 `\boxed{...}`，先解开；预测必须已经通过外层 final/boxed 门控，不再次从预测的局部片段抽答案。两边将 `°` 统一为 `^\circ`。完整字符串忽略大小写一致可直接通过，这允许复杂结构的原样正确答案。
2. **同变量多根的窄分支：** 只有 gold 是完整的 2–8 项逗号赋值列表、每项均为同一个 ASCII 单字母变量（可带数字下标），才视为根的无序多重集合。例如 `$x_1=-3$, $x_2=2$`。每项右侧必须完整，不含额外等式、不等式、分号或逗号。预测可以是同变量的完整赋值列表，也可以是完整无标签根列表/集合；必须根数一致、每个根等价、重数一致，没有缺项或多余项。
3. **普通顶层逗号列表按位置逐项比较。** 保留顺序、长度和重复次数。例如 gold `5,8` 与预测 `8,5` 不等价；gold `1,1,2` 也不能被 `1,2` 替代。合法千分位数值如 `4,000` 是数值 4000，不拆成两个答案；`1,2` 不会通过删除逗号误变成 12。显式集合仍走其符号表达式路径，不把所有逗号和坐标一律转换成集合。
4. **多变量赋值不进入同变量根分支。** 例如 `x=1,y=2` 的普通列表按位比较，必须保留变量绑定；重排成 `y=2,x=1` 即使数学上等价也可能保守记错。坐标及有顺序的答案不新增无序比较后门。
5. 其他情况只处理单个完整数学表达式：最多解开一层 `$...$`、`$$...$$`、`\(...\)` 或 `\[...\]`；残留 `$`、LaTeX 行分隔 `\\`、嵌套抽取标记 `\boxed`、`\begin/\end`、空字符串或超过 4,096 字符等情况拒绝进入符号解析。这样避免“前半句正确、后半句错误”被解析器只取前缀奖励。
6. 两边均为有限数值时用 `rel_tol=1e-6, abs_tol=1e-8`。其余由 **Math-Verify 0.8.0** 的 LaTeX extraction 与 `verify(gold,pred)` 判断：`boxed_match_priority=-1`、`fallback_mode=no_fallback`、`extraction_mode=first_match`。指定的解析/算术异常记错；缺少 verifier 属于运行配置错误，不静默当作模型全错。

| gold | 预测 boxed 内文 | 规则含义 |
|---|---|---|
| `$x_1=-3$, $x_2=2$` | `x_1=-3, x_2=2` 或 `-3,2` 或 `2,-3` | 同变量完整多根，允许换序 |
| `$x_1=-3$, $x_2=2$` | `-3` 或 `-3,2,7` | 缺根或多根，拒绝 |
| `5,8` | `8,5` | 普通列表保序，拒绝 |
| `x=1,y=2` | `x=2,y=1` | 变量值被交换，拒绝 |
| `4,000` | `4000` | 合法千分位数值可等价 |
| `\frac{1}{2}` | `0.5` | 数值或符号等价 |

这次实际 smoke 暴露了 MMK12 同变量多根的格式假阴性，随后又复现 Math-Verify 将普通逗号列表当集合导致的顺序假阳性，因此增加了上述两个受限分支。修复没有把任意多段表达、联立方程、坐标、函数列表都当成根集合。复杂矩阵、分段函数或多行方程在非原样表述下仍可能有假阴性；文档和论文应保留这一验证覆盖范围。

最终奖励 SHA256 见第 8 节。[参考答案审计](../logs/reward_reference_audit.json) 对 Geometry3K 2,101、MMK12 8,000、ViRL39K 9,480 条归一化记录逐条构造参考 final，合计 **19,581 条全部通过**；另有 13 个错误答案/安全边界检查通过。对旧 smoke 的 32 条真实响应重算，只有同一 MMK12 题的 8 条响应从 0 修正为 1，其余不变，见 [修正审计](../logs/reward_multiroot_correction.json)。参考自检证明这些 gold 表示可被当前实现接收，不等于模型已获得正确率，也不证明所有不正确答案都能被判错。

### 5.4 VQAv2：保留标注重数的共识分

对预测与十位标注者答案做 VQA 文本规范化：小写、空白、规定标点处理、冠词去除、数字词与撇号写法统一。**不能先把十个答案去重**，重复次数正是共识证据。设 \(N=10\)，\(\nu\) 为该规范化，奖励按 leave-one-annotator-out 定义：

\[
r_{\mathrm{VQA}}=\frac{1}{N}\sum_{k=1}^{N}
\min\left(\frac{\sum_{j\ne k}\mathbf1[\nu(p)=\nu(a_j)]}{3},1\right).
\]

预测在十个参考中匹配 0、1、2、3、至少 4 次时，分数分别为 0、0.3、0.6、0.9、1。不是简单使用 `min(匹配总数/3,1)`。输出例如 `\boxed{two}`。该软分数同时写入 `score` 和 `accuracy` 字段。

### 5.5 DocVQA：ANLS

预测与参考先小写、去首尾空白。对每个参考 \(a\)，令 \(d(p,a)\) 为字符级 Levenshtein 距离：

\[
s(p,a)=1-\frac{d(p,a)}{\max(|p|,|a|,1)},\qquad
r_{\mathrm{Doc}}=\max_{a\in\mathcal A}\begin{cases}s(p,a),&s(p,a)>0.5,\\0,&s(p,a)\le0.5.\end{cases}
\]

阈值严格为 `similarity > 0.5`，等价于归一化编辑距离小于 0.5。多个合法参考取最大值；输出仍要求 `\boxed{...}`。这允许小范围 OCR 拼写差异，最终奖励可以是 0 到 1 的连续值。

### 5.6 ChartQA：宽松数值 / 文本精确匹配

预测与任一参考去首尾空白、忽略大小写后完全一致即可得 1。若双方均可解析为有限数值，再用：

\[
|p-a|\le\max(0.05|a|,10^{-8})
\]

判断是否得 1，否则为 0；gold 为 0 时使用绝对容差 \(10^{-8}\)。数值解析支持分数、百分数与合法千分位；其他文本没有开放式语义 judge。输出为 `\boxed{...}`，格式本身不增加分数。

### 5.7 RefCOCO：连续 IoU

输出形如 `\boxed{[x1,y1,x2,y2]}`，框坐标在原图归一化的 `[0,1000]` 范围，语义为 xyxy。boxed 内必须可解析为长度 4 的 JSON 数组；元素必须是有限 int/float，布尔值不算数字；要求 `x2>x1`、`y2>y1`。非法格式、越界、非有限或退化框均为 0。

\[
r_{\mathrm{bbox}}=\operatorname{IoU}(B,\widehat B)
=\frac{|B\cap\widehat B|}{|B|+|\widehat B|-|B\cap\widehat B|}.
\]

**训练使用连续 IoU**，而日志 `accuracy` 使用 \(\mathbf1[\mathrm{IoU}\ge0.5]\)。两者不应混淆；连续分值为部分定位改善提供组内相对信号。

### 5.8 IF 格式：JSON 门控乘内容共识分

IF 的底层问题仍来自具有十个人工答案的 VQAv2，`content_task=vqa`。最终输出例子为 `{"answer":"two"}`，只能有这一个字符串字段。奖励为：

\[
r_{\mathrm{IF}}=\mathbf1[\text{严格 JSON 结构通过}]\times r_{\mathrm{VQA}}(\text{answer字段}).
\]

缺键、多键、重复键、非字符串、代码围栏、额外说明文字均为 0；`{"answer":"wrong"}` 即使语法正确也不会获得格式分。本轮没有“先学格式即可拿满分”的独立格式奖励。

### 7.2 保存与失败恢复

每 25 step 和最终 step 100 同步保存模型、optimizer、extra（含 RNG/scheduler）与 dataloader 状态，最近两个 checkpoint 保留。位置为 `runs/<teacher>/checkpoints/`，`latest_checkpointed_iteration.txt` 指示可恢复位置。中断后再次以相同入口执行，会从已有 checkpoint 自动续跑；尚未保存的更新可能重做，但已保存的训练结果保留。

每次运行保存 `protocol.json`，包含数据、奖励、训练代码、仓库差异、环境文件 SHA256 和 rollout seed 映射；同时冻结 `resolved_config.yaml`。续跑时两者必须一致，数据或代码改动不能静默接着同一实验训练。新 R/G 入口在 step 100 已完成时只处理导出；现有感知由边界 watcher 结束后仅导出 100，不以新配置续跑原训练。

HF 合并在 CPU 上写入新的 `.merging.<pid>` 临时目录，验证 `config.json` 和 safetensors 存在后才写入 `sharedexpert_export_complete.json` 并原子改名。原 FSDP shards 保留；失败可单独 `--merge-only` 重试。已完整导出的目标直接复用，不覆盖为半成品。

编排失败会记录 `failed` 和具体错误并退出；重启时各教师 launcher 根据已有 checkpoint 续跑，完成的教师只检查/导出。评测也保存逐题原始响应缓存：与冻结模型/清单/协议一致的完成条目可复用，未完成或出错条目继续执行，不把失败题静默当作正式分数。没有自动更改学习率、batch、数据或奖励来绕过失败。

### 7.9 第二步 CUDA OOM 与无用蒸馏分支的修复验证
